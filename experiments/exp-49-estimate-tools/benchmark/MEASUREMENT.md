# Ведомость EXP-49
Одна попытка на ячейку сценарий × A/B × клиент. Матрица 400 плановых ячеек. Обычный чат без инструментов поддерживает A. B применим при доказанном вызове того же ядра. Отмечать недоступные сочетания N/A с причиной, ошибки начатых попыток сохранять в знаменателе. Парные сравнения только внутри одной поверхности и на совпадающих ID. Зафиксировать регион, язык, версии, порядок, контрольный HTML (URL, дата, SHA), прежний путь и бюджет до старта. Репозиторий содержит учебный корпус; модель получает только выбранный prompt и разрешённый контракт. Ключ и журнал оценки изолировать от контекста и поиска модели.

Адаптер каждого клиента должен в момент отправки сериализовать фактический текст запроса, в момент поступления собрать упорядоченные фрагменты текста ответа без преобразований, на последнем событии снять время теми же монотонными часами. Времена задаёт источник событий. Сохранять отдельно текст и транспортные байты. Связывать события с ID сообщения/модели; в парном UI время завершения отдельно для каждой модели. Формат JSON для capture.py: поля provenance из скрипта, expected_request_sha256 из заранее запечатанного запроса, events с kind, monotonic_ns и base64 data для send/text. Поле complete содержит конечную отметку. Исходник хранить закрыто без cookies, токенов и персональных данных. Не отправлять в модель ключ или сырые логи. Скрипт проверяет переданные данные, источник событий проверяется отдельно. Только рендер, скриншоты, Thought for или отсутствие событий означают BLOCKED для точных метрик.

Для каждого ответа рецензент записывает фактические позиции, пропуски и лишние позиции, неверные поля, итог, валюту, версию, корректность действия и раскрытия. Сверяет количество, единицы, материал, фурнитуру, цену, услуги, налоговые условия, дату, источник, предварительный статус с fixture.json и review-key.json. Неизвестную ставку уточнить. При утечке или уверенной выдуманной ставке немедленно прекратить эксперимент.

Метрики отдельно по каждой группе:
- Верные ожидаемые строки / все ожидаемые строки. Точная смета требует совпадения всех полей, итога и отсутствия лишних строк. Знаменатель — все начатые расчётные случаи.
- Ошибка в ₸ = полученный итог минус эталон; медиана абсолютной ошибки и максимум только по числовым парам. Отдельно число отсутствующих итогов.
- Корректные отказы, уточнения и выход за рамки считать отдельно / все ожидаемые действия соответствующего вида. Выставленная цена в отрицательном случае — ошибка.
- Принято без правок / все переданные менеджеру сметы. Фиксировать причину правки и время активной проверки от открытия до решения, паузы отдельно. Сравнить медиану с ручным контролем на тех же ID. Непроверенные сметы показывать отдельно.
- Случаи раскрытия / все ответы, сбои / все попытки, часы и добавочные KZT, источник расходов. Нулевой знаменатель — N/A.
